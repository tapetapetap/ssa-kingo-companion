# 운영자 판정 검토 화면 구성(US7, T076)

PC 화면 하나(`/ops/`). Figma 없이 astryx(`@astryxdesign/core` 0.7.17)로 바로 만든다(사용자 결정 2026-11-18, 2026-11-23). 강조색은 기본 테마다. 틀은 `npx astryx build`가 고른 것 가운데 `incident-console`(목록 + 오른쪽 상세, StyleX 컴파일러가 필요 없음)이다. 템플릿의 머리 | 행 목록 | 오른쪽 칸 틀과 간격을 그대로 두고 내용만 바꾼다.

## 영역

| 영역 | 내용 | astryx 컴포넌트 |
|---|---|---|
| 머리 | 제목 '판정 검토', 아직 확인 안 한 수, 이유 거르기, '확인한 것도 보기', 나가기 | `LayoutHeader`, `Heading`, `Text`, `SegmentedControl`, `Switch`, `Button` |
| 왼쪽 목록 | 확인할 것 한 줄씩: 제목, 이유·게시일, 확인했으면 '확인함' 표 | `List`, `ListItem`, `Token`, `EmptyState` |
| 오른쪽 칸(위) | 제목, 원문 링크, 파일 판정과 판정한 곳 | `Heading`, `Link`(새 탭), `MetadataList` |
| 오른쪽 칸(가운데) | 고치는 칸: 공지예요(켜고 끔), 종류, 마감(지우면 '마감 없음'), 핵심 분야(2개까지), 관련 분야(5개까지). 칸마다 설명에 '파일 값: …'과 운영자가 고쳤으면 누가. 바꾼 칸만 보낸다. 주 버튼은 하나: 고친 것이 없으면 맞아요, 있으면 저장. 다시 판정, 되돌리기 | `Switch`, `Selector`, `DateInput`(hasClear), `MultiSelector`(hasSearch, 분야 묶음별 구역), `Button` |
| 오른쪽 칸(아래) | 고친 기록: 언제·누가·무엇을(칸, 앞 값 → 새 값) | `List`, `ListItem`, `Timestamp` |
| 알림 | 저장·맞아요·다시 판정 결과, 서버 오류 글 | `useToast` |
| 넘어가기 확인 | 저장하지 않은 값이 있는데 다른 줄을 고르면 '저장하지 않은 값이 있어요'(버리고 넘어가기·계속 고치기) | `AlertDialog` |

이유 이름: `review:<이유>` → '확인 필요: <이유>', `no_deadline` → '마감 없음', `no_fields` → '분야 칸 빔'.

## 상태별 화면

| 상태 | 보이는 것 |
|---|---|
| 불러오는 중 | 가운데 `Spinner`와 '불러오는 중이에요' |
| 로그인 | `/api/ops/review`가 `login_required`면 가운데 카드에 이메일·비밀번호 칸과 '들어가기'(개발 로그인). 틀리면 칸 아래 서버의 `message` |
| 권한 없음 | `forbidden`이면 `EmptyState` '운영자 계정이 아니에요'와 '다른 계정으로 들어가기'(나가기) |
| 오류 | 그 밖의 실패는 `EmptyState` '불러오지 못했어요'와 '다시 불러오기' |
| 빈 목록 | 거른 결과가 없으면 왼쪽에 `EmptyState` '확인할 것이 없어요'. 오른쪽은 '왼쪽에서 공지를 고르세요' |

## 지키는 것

- 자료는 `/api/ops/*`와 분야 목록(`/api/fields`), 로그인(`/api/login`, `/api/logout`)만 쓴다. 학생 자료는 받지 않는다(FR-055).
- 다시 판정은 모델을 바로 부르지 않는다. 버튼 설명에 '다음 매일 작업에서 다시 판정해요'라고 적는다(FR-054).
- 화면 너비 1024px 이하는 고려하지 않는다(PC 화면). 템플릿의 좁은 화면 아래 칸(BottomSheet)은 쓰지 않는다.
- 처리하면(저장·맞아요·다시 판정) 목록을 다시 받고, 처리한 공지가 빠졌으면 그 아래 공지를 연다. 머리에 '남은 것 n개'.
- 컴포넌트 글은 `InternationalizationProvider`의 `ko-KR`로 한국어다. 남은 영어는 라이브러리 안의 화살표 이름(`Left arrow`·`Right arrow`)뿐이다.
