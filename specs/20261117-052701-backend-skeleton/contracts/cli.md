# 명령 계약: 운영자가 서버 컴퓨터에서 쓰는 것

`node server/cli.ts <명령>`(npm 스크립트 `npm run cli -- <명령>`은 `.env`를 읽는다. Docker에서는 `docker compose run --rm jobs node server/cli.ts <명령>`). 넣기·계정·백업·상태 보기는 명령으로만 한다(FR-014).

| 명령 | 하는 일 | 근거 |
|---|---|---|
| `migrate` | 스키마 바꾸기를 번호 순서로 적용 | R4 |
| `ingest <결과 파일> --taxonomy <id> [--switch] [--dry-run]` | 결과 파일과 분야 목록을 검사하고 넣기. `--dry-run`은 요약만 내고 바꾸지 않음. 활성 목록과 다른 `<id>`는 `--switch`가 있어야 갈아탐 | US1, FR-002~008, R11 |
| `account create <이메일> [--dept <학과>]` | 개발 계정 만들기. 비밀번호는 표준 입력으로 받음(명령 기록에 남지 않게) | FR-011 |
| `account password <이메일>` | 개발 계정 비밀번호 다시 정하기 | FR-011 |
| `account delete <이메일>` | 개발 계정과 그 학생 자료 지우기 | FR-011, FR-020 |
| `status` | 아래 '상태 보기' | FR-045 |
| `daily [--skip-classifier]` | 매일 작업 한 번(research R14) | FR-043 |
| `backup` | 백업 한 번 | FR-046, R15 |
| `restore <백업 파일>` | 빈 DB에 되살리기 | FR-046, R15 |
| `export-gold <폴더>` | 고친 공지를 정답셋 후보로 내보내기. 저장소 안 경로는 거절 | FR-053 |

- 운영 모드에서 `account create`·`account password`는 거절한다(FR-012). `account delete`는 운영 모드에서도 된다(남아 있는 개발 계정을 지우는 길이다).
- 끝 코드: 0 성공, 1 거절·실패, 2 쓰는 법이 틀림.
- 출력: 한 줄 요약(한국어). `--json`이면 같은 내용을 JSON으로.
- 출력과 기록에는 비밀번호, 토큰, 공지 본문을 남기지 않는다(FR-047).

## 넣기

- 요약 예: `새 3 · 바뀜 2 · 그대로 121 · 내려감 1 · 되살림 0 · 확인 필요 4 · 사람 판정 유지 0 · 벡터 보관 125 / 새로 1 / 못 만듦 0 · 분야 목록 custom(2026-11-19, 고르지 않은 안)`
- 새·바뀜·그대로는 파일의 기회만 세고, 확인 필요 글은 '확인 필요'로 따로 센다(research R11).
- 거절 예: `넣지 않았어요: opportunities[17].fields.core[0] 'web-x'는 분야 목록 custom에 없어요`
- 활성 목록과 다른 목록: `넣지 않았어요: 지금 분야 목록은 custom이에요. ncs로 갈아타려면 --switch를 붙여요(고른 분야와 활동·사람 판정의 분야가 지워져요)`
- 갈아탄 때는 요약 끝에 `· 목록 바꿈 custom → ncs(고른 분야 n명 지움)`이 붙는다.

## 상태 보기

`status`는 다섯 줄을 낸다. 하나라도 닿지 못하면 그 줄에 이유를 적고 끝 코드는 1이다. 예:

```text
DB: 닿음 · 적용 안 된 바꾸기 0
마지막 매일 작업: 2026-11-20 03:41 끝 · 실패한 단계 없음
마지막 넣기: 2026-11-20 03:12 · 새 3 · 바뀜 2 · 그대로 121 · 내려감 1 · …
모델 서버: 닿음(gemma4:12b, bge-m3)
api: 닿음 · 다시 고르기 줄 0
```

| 줄 | 확인하는 것 |
|---|---|
| DB | 연결과 적용 안 된 스키마 바꾸기 수 |
| 마지막 매일 작업 | `daily_runs`의 마지막 줄(끝난 때, 실패한 단계) |
| 마지막 넣기 | `ingest_runs`의 마지막 줄(요약 또는 거절 이유) |
| 모델 서버 | `OLLAMA_HOST`의 `/api/tags`에 닿는지 |
| api | `KINGO_API_URL`의 `GET /api/health`(compose에서는 문지기를 거쳐 닿는지 본다)와 다시 고르기 줄 길이 |

## 백업과 되살리기

- `backup`은 `KINGO_BACKUP_DIR/kingo-YYYY-MM-DD.dump`(한국 날짜)를 쓴다. 같은 날 다시 돌리면 덮어쓴다. 이름의 날짜가 오늘보다 7일 이상 앞선 파일을 지운다(7개가 남는다).
- `restore`는 대상 DB가 비어 있을 때만 한다(`students`와 `notices` 표가 없거나 둘 다 0행). 아니면 `되살리지 않았어요: DB가 비어 있지 않아요`와 1이다.

## 정답셋 후보 내보내기

`export-gold <폴더>`는 사람 판정이 하나라도 있는 공지를 `<폴더>/gold-candidates-YYYY-MM-DD.csv`(UTF-8, 머리줄 있음)에 쓴다. 값은 학생에게 보이는 값이다.

| 칸 | 값 |
|---|---|
| 링크, 제목, 게시일, 주최 | 공지의 값 |
| 기회 | `O`·`X`(`is_notice`) |
| 종류 | 종류 이름(없으면 빈칸) |
| 마감 | `YYYY-MM-DD`(없으면 빈칸) |
| 핵심 분야, 관련 분야 | 분야 id를 세로줄로 이음. 분야 없음은 `-`, 분야가 붙지 않은 공지는 빈칸 |
| 고친 칸 | 사람 판정이 있는 칸 이름을 세로줄로 이음 |
| 고친 때 | 마지막으로 고친 때 |

예: `"https://…articleNo=228336","[가나다] 인턴 모집","2026-11-10","가나다","O","채용","2026-11-19","backend","-","kind|fields","2026-11-20T10:02:00+09:00"`

1단계 정답셋 파일(스펙 1 `contracts/gold-csv.md`)과 같은 꼴은 아니다(서버에는 게시판 칸이 없다). 사람이 정답셋에 옮길 때 쓰는 후보다. 정답 라벨이라 저장소 안 경로에는 쓰지 않는다.
