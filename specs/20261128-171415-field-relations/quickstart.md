# Quickstart: 운영자 '분야 체계' 확인하기

앞 단계 quickstart(`specs/20261125-171634-student-app/quickstart.md`)로 DB·서버·운영자 계정이 떠 있다고 본다.

## 1. 보기

1. `npm run build:ops && npm run server`로 띄우고 운영자로 로그인해 '분야 체계'를 연다.
2. 지금 판이 '바탕'이고, 묶음 11개 TREE와 분야 91개가 나오는지 본다.
3. 'LLM'을 골라 정의·CSRankings·과목 영역·공지 수·가까운 분야 5개가 나오는지 본다. 넣기 전이면 공지 수 0과 '아직 벡터가 없어요'가 나온다.
4. 'MAP' 탭에서 노드를 눌러 자세히가 바뀌는지 본다. 새로 고쳐도 같은 자리에 그려지는지 본다.

## 2. 고치기

1. 'LLM'에 동의어 '거대언어모델', 'GPT'를 넣고 저장한다. TREE에 '고침', 위 카드에 '고친 분야 1개'.
2. 다른 분야 이름('자연어처리')을 'LLM'의 동의어로 넣어 겹침 알림이 나오는지 본다.
3. 창 둘에서 같은 분야를 고쳐, 나중 저장이 "다른 운영자가 먼저 고쳤어요"로 막히는지 본다.
4. 학생 앱의 분야 고르기 화면에 정의가 그대로이고 동의어가 없는지 본다.

## 3. 초안 재기와 적용(이 맥, 정답셋 필요)

1. '초안 재기'를 누르고, 밤 시간(22:00~02:50)에 `npm run cli -- requests`를 한 번 돌린다(10분 타이머가 하는 일). 낮에는 요청이 '오늘 밤에 재요'로 기다린다.
2. 결과가 지금 판과 나란히 나오는지, 85% 이상이면 적용이 열리는지 본다.
3. 적용한다. 판 기록에 `<오늘>-1`, 다음 `requests`에서 `etl/taxonomy/versions/custom-<오늘>-1.json`이 생기는지 본다.
4. 분류기를 켠 매일 작업(`npm run cli -- daily`)을 한 번 돌려, 분류기 줄에 판 파일 경로가 쓰였는지와 분야가 들어갔는지(결과 파일의 `field.reason`이 없음) 본다.
5. SC-007: 이 결과의 재현율·정밀도를 tasks.md에 적는다.

## 4. 되돌리기

1. 판 기록에서 '바탕으로 되돌리기'를 누른다. 근거가 맞으면 바로 바탕, 아니면 '초안으로 불러오기'가 열린다.
2. 다시 적용한 판으로 되돌린다. 판 이름이 새로 생기지 않고 기록에 '되돌림'이 남는지 본다.

## 5. 자동 검사

```sh
npx tsc --noEmit
npx vitest run
npm run build:ops && npm run e2e:ops   # 이 단계에서 새로 만드는 운영 화면 검사('분야 체계' 걸음)
```
